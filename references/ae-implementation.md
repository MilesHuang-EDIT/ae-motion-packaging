# AE 实现

## 原生工程

先核实当前机器的 AE、字体、素材路径和可用自动化方式。历史项目使用 macOS AE 2026，不代表新环境也如此。只使用当前环境提供并有文档的应用控制 API。

可采用 `SEGMENTS`、`SHOTS`、`EDIT_COPY`、`REPLACE_VIDEO` 分类，磁盘放 `assets`、`fonts`、`source`、`previews`、`qa`。结构可调整，正式输出和素材替换位置要易于找到。

原生文字/形状负责可编辑信息，环境与材质可以是图片。展示框的材质、固定方式、光照和透视应与场景匹配，不用一种铁架硬套所有背景。

## JSX 与稳定操作

使用 ExtendScript 时注意 ES3 兼容性，不假定支持 `Array.indexOf` 等现代 JS API。对属性先查关键帧：静态 `setValue`，关键帧 `setValueAtKey` / `setValueAtTime`。删除图层后不继续访问旧对象。某些时间重映射操作删除最后关键帧后会使属性不可用，应保留一个有效关键帧并重新检查引用。

改 Source Text 时保留需延续的字重、段落属性及关键帧时间；用实际安装的 PostScript 字体名验证，另检查字形缺失与回退。

先保护当前工程及用户未保存的修改。脚本定位校验名称、类型和预期数量，找不到目标不猜着修改别的合成。

若 AE 拒绝脚本文件写入，不自动修改“允许脚本写入文件和访问网络”。可核实原生保存 AEP/AEPX、在 FolderItem.comment 存小份审计 JSON 后解析 AEPX、由终端复制文件等现有替代方式；以当前授权与工具能力为限。

UI 进度卡住或超时，先看文件时间与验证产物，避免重跑已完成脚本。可用核实的完整应用路径重新绑定 UI；操作索引取自最新状态，不为读取界面反复重启/终止用户工程。

## 空间与边界

用多个深度平面/原生相机建立空间。检查相机路径的所有运动阶段：只看首尾发现不了穿行时露底。招牌和机械构件在阅读状态不应意外出画。

背景压暗放在目标背景之上、主体和文字之下。纯黑 Solid、深色调色层和整体曝光不是同一种效果；用户指定黑色及不透明度时精确实现，不自动套用历史40%。

替换预合成保留约定尺寸、帧率与时长，说明裁切/完整显示方式，避免通过更改素材预合成尺寸破坏主工程。

## 渲染和单段提取

核实当前 `aerender` 路径、队列模板及本地化设置。案例曾使用：

```sh
"/Applications/Adobe After Effects 2026/aerender" -project "/absolute/project.aep" -v ERRORS_AND_PROGRESS
```

不要一边渲染同一工程，一边修改/保存它。核对输出模块是否真正接受音频等设置；通过实际媒体文件验证结果。

单段提取在副本中清理不需要的队列引用，再对目标用原生 Reduce Project，保留实际依赖的预合成和素材。检查仍被引用但不在本段可见时间内的内容，不误删有用依赖。复制剩余外部素材，重连本地路径，保存新 AEP，不覆盖原工程。
